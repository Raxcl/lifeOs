# 周—月—年目标关系页设计

日期：2026-10-28

## 1. 目标

新增“目标关系”页，把当前周、当前月、当前年的计划放在三列中，用持续跟随卡片位置的连线展示目标拆解链路。

页面支持三类操作：

1. 上下拖动卡片调整顺序，连线随卡片实时移动。
2. 从周卡连接到月卡、从月卡连接到年卡，写回现有 `parent_id`。
3. 断开不再成立的上级关系。

本页不替代日记页或收集箱页：日记负责执行，收集箱负责归属与维护，关系页负责查看和调整目标链路。

## 2. 已确认的产品规则

1. 第一版只展示当前周、当前月、今年，不提供历史或未来周期切换。
2. 三列固定为左到右：本周 → 本月 → 今年。
3. 周、月事项来自 `items.csv`；年度目标来自 `annual-goals.csv`，年度目标不并表。
4. 所有当前周期事项都显示，包括已完成和未关联事项。
5. 已完成卡片弱化显示；未关联卡片正常显示但不画线。
6. 排序与连线是两种独立手势：拖手柄只排序，拖连接点只改关系。
7. 周卡只能连接当前月卡，月卡只能连接今年卡；不支持跨周期连接、多父级或反向连接。
8. 手动顺序永久保存，刷新、重启和同步后仍保持。
9. 窄屏保持三列并横向滚动，不把三列上下堆叠。
10. 操作完成后自动保存；保存失败撤销本次操作并提示。

## 3. 页面与导航

### 3.1 新页面

新增：

- `desktop/app/目标关系.html`
- `desktop/app/assets/目标关系.js`
- `desktop/app/assets/目标关系.css`

沿用现有原生 HTML/CSS/JavaScript、本地壁纸与设计变量，不引入前端框架、拖拽库或 SVG 库。

### 3.2 入口

日记页“看见未来”标题区增加“目标关系 →”链接，进入 `目标关系.html`。

### 3.3 页面结构

页面包含：

- 标题与当前周期说明：本周日期范围、本月、今年。
- 保存状态与错误提示。
- 三列关系画布：
  - 本周： `scope=week && period=当前周一`。
  - 本月： `scope=month && period=当前年月`。
  - 今年：当前 `annual_goals.years` 记录中的事项。
- 一张覆盖整个关系画布的 SVG 连线层。

每列内部卡片按 `sort_order` 升序排列，再按 `created_at`、`id` 保证稳定顺序。

## 4. 数据模型与兼容

### 4.1 `items.csv`

在现有末尾追加 `sort_order`：

```text
item_id,text,done,note,scope,period,parent_id,created_at,updated_at,sort_order
```

`PlanItem` 增加：

```rust
#[serde(default)]
sort_order: u64,
```

规则：

- `sort_order` 在相同 `scope + period` 分组内生效，不要求全局唯一。
- 旧 CSV 缺少该列时按 `0` 读取，不报错；既有排序键保证旧数据顺序不变。
- 后端排序调整为 `scope, period, sort_order, created_at, id`。
- 新增事项的 `sort_order=0` 表示未指定，后端在同组现有最大值的末尾补位。
- `upsert_plan_items` 比较和更新 `sort_order`，变化时更新 `updated_at`。
- 日记、收集箱和首页读取、规范化 PlanItem 时保留该字段，不能因其他页面保存而丢失。

### 4.2 `annual-goals.csv`

在现有末尾追加 `sort_order`，`AnnualGoalItem` 同样增加：

```rust
#[serde(default)]
sort_order: u64,
```

规则：

- `sort_order` 在同一个年份分组内生效。
- 旧数据缺列按 `0` 处理，保持既有创建时间顺序。
- 新年度目标默认排在所属年份末尾。
- 日记与年度目标管理页保存时保留该字段。

### 4.3 首次排序

旧数据可能全部为 `0`。关系页第一次完成手动排序时，只把当前受影响列规范化为连续的 `1..N`，其他周期和年份不被无谓改写。

`schema_version` 保持 `1`：本次只是追加可缺省列，沿用现有 CSV 缺列兼容能力。

## 5. 数据读取与保存

### 5.1 读取

复用 `get_database_manager`，取得完整 `items` 与 `annual_goals` 快照后，在前端筛选当前三列。

浏览器直开时复用：

- `lifeos-db:items`
- `lifeos-db:annual-goals`

fallback 读写与 Rust 使用相同字段和排序规则。

### 5.2 保存

复用现有命令，不新增关系表或关系命令：

- 周/月排序、周→月连线、月→年连线、断开这些关系：`save_plan_item_database`。
- 年度目标排序：`save_annual_goal_database`。

页面始终保留完整数据库快照，保存时把修改合并回完整快照，不能只提交当前三列而删除其他周期数据。

每次操作只保存受影响的一张表。保存期间暂时禁止新的排序或连线，避免并发保存和回滚互相覆盖。

### 5.3 失败回滚

每次操作前记录受影响卡片的：

- `parent_id`
- 当前列的 `sort_order`

保存失败时恢复操作前状态、重新渲染卡片和连线，并显示错误。成功后更新本地快照与保存状态。

## 6. 卡片与连线渲染

### 6.1 卡片

卡片显示：

- 事项文本。
- 完成状态样式。
- 排序手柄。
- 周卡和月卡的右侧连接点。
- 已有上级时的“断开上级”按钮。
- `parent_id` 非空但目标不在当前可见列时的“上级不可用”标记。

本页不提供文本编辑、新增、删除、完成勾选或周期修改。

### 6.2 正式连线

连线完全由数据生成：

- 周卡 `parent_id` 等于当前月卡 `id`：周卡右侧中点 → 月卡左侧中点。
- 月卡 `parent_id` 等于今年卡 `id`：月卡右侧中点 → 今年卡左侧中点。

多张周卡可以连接同一张月卡，多张月卡可以连接同一张年卡；每个子项仍只有一个 `parent_id`。

SVG：

- 绝对定位在关系画布内，`pointer-events: none`，不拦截卡片操作。
- 尺寸覆盖完整可滚动画布，随内容一起横向滚动。
- 使用三次贝塞尔曲线，水平控制点取两端横向距离的一半。
- 坐标由卡片 `getBoundingClientRect()` 转换为画布坐标。

### 6.3 重绘时机

使用 `requestAnimationFrame` 合并重绘：

- 排序拖动过程中。
- 手动连线过程中。
- 连线或断开完成后。
- 卡片或画布尺寸变化时，通过 `ResizeObserver` 观察。
- 页面加载、字体完成和窗口尺寸变化后。

只在需要时重绘，不运行永久动画循环。

## 7. 拖拽排序

采用 Pointer Events，不使用 HTML5 拖放 API，以便在移动过程中持续获得卡片位置并重绘 SVG。

流程：

1. 在排序手柄上 `pointerdown`，记录原顺序并捕获指针。
2. `pointermove` 时拖动的卡片跟随纵向位移；根据指针位置计算插入点，实时调整同列其他卡片的 DOM 顺序。
3. 每帧读取最新卡片位置并重绘正式连线。
4. `pointerup` 后清除拖动样式，把当前列规范化为 `1..N`，保存受影响数据库。
5. `pointercancel` 或保存失败时恢复原顺序，不写或撤销本次修改。

拖动不能跨列；拖到列外只改变本列插入位置，不改变 `scope`、`period` 或 `parent_id`。

## 8. 手动连线与断开

### 8.1 连接

1. 从周卡或月卡的右侧连接点按下，开始一条临时 SVG 曲线。
2. 临时线从源卡片右侧中点跟随指针，合法目标列卡片高亮。
3. 周卡的合法目标仅为当前月卡；月卡的合法目标仅为今年卡。
4. 在合法目标上松开，设置子项 `parent_id=目标 id` 并保存。
5. 若已有上级，连接新目标会替换旧 `parent_id`。
6. 连接原上级属于无变化操作，不重复写文件。
7. 在空白、非法目标上松开或收到 `pointercancel`，取消操作，原关系不变。

### 8.2 断开

有可见上级的卡片提供“断开上级”操作，将 `parent_id` 置空并保存。用户不需要精确点击 SVG 细线。

“上级不可用”的卡片也允许断开，用于清理悬空引用。

## 9. 响应式与视觉

- 宽屏三列等宽，卡片间距与现有日记页保持一致。
- 关系画布设置可读的列最小宽度；空间不足时容器横向滚动，三列不堆叠。
- SVG 与卡片使用同一滚动内容坐标系，横向滚动不需要重新计算关系。
- 正式连线使用低对比度前景色，临时连线和合法目标高亮使用现有强调色。
- 拖动卡片有明确的层级与阴影，但连线仍保持可见并持续连接。
- 尊重系统“减少动态效果”设置，取消非必要过渡，不影响拖拽和连线功能。

## 10. 错误与边界

- 数据库读取失败：显示错误，不渲染可编辑画布。
- 保存失败：回滚当前操作并保留页面可用状态。
- 空列：显示空状态，其他列和已有可见关系正常工作。
- 悬空、跨周期或跨层级 `parent_id`：不画线，不自动修复数据，只标记并允许断开。
- 快速重复操作：保存期间禁用排序和连线，避免旧快照覆盖新操作。
- 页面离开时有未完成保存：阻止静默丢失，待保存结束后再允许离开或明确提示。

## 11. 不做

- 历史或未来周期切换。
- 跨周期、跨层级、多父级或反向连接。
- 在关系页新增、编辑、删除、勾选完成事项。
- 自动推断或自动建立父子关系。
- 年度目标并入 `items.csv`。
- 日计划、三只青蛙或习惯进入关系图。
- 窄屏三列上下堆叠。
- 第三方拖拽、图形或前端框架依赖。

## 12. 测试与验收

### 12.1 Rust

在现有测试模块覆盖：

- 旧 `items.csv` / `annual-goals.csv` 缺少 `sort_order` 时可读取，顺序不变。
- 新字段 CSV round-trip 保留。
- 新事项未指定顺序时排在同组末尾。
- upsert 修改 `sort_order` 会保存并更新 `updated_at`，未修改不误写。
- 关系页复用的全量保存仍保留其他周期事项。

### 12.2 浏览器真实交互

在真实 Chrome 中覆盖：

- 三列分别只显示当前周、当前月、今年。
- 连线端点与 `parent_id` 一致，多条关系同时显示。
- 上下拖动时连线持续跟随，落点后顺序和端点正确。
- 刷新后三列手动顺序保持。
- 周→月、月→年手动连线成功；重新连接会替换旧上级。
- 非法目标和空白处松开不改变数据。
- 断开上级后连线和 `parent_id` 同时移除。
- 保存失败时顺序或关系回滚。
- 窄屏出现横向滚动，三列不堆叠，连线位置仍正确。
- 浏览器控制台无未处理错误。

### 12.3 真实 Tauri 链路

使用隔离 vault 验收：

- 旧 CSV 无 `sort_order` 可直接打开关系页。
- 排序后写回正确 CSV，重启应用顺序保持。
- 连线、替换和断开正确写回 `parent_id`。
- 保存周/月关系不影响其他周期、收集箱事项或年度目标。
- 年度目标排序不影响 PlanItem。
- 日记页与收集箱页重新打开后数据一致，且未丢失 `sort_order`。

浏览器 localStorage fallback 跑同一组核心流程。
